# 部署脚本与配置审查

审查日期：2026-09-11。范围包括主 Compose、Whisper/CosyVoice 覆盖文件、前后端 Dockerfile、Nginx gateway、部署/回滚脚本、配置生成与校验、后端环境变量读取。

## 本轮已修复

1. **前端帧率配置在生产失效。** `VITE_LIVE2D_TARGET_FPS` 原先只存在于模板和配置向导，没有作为 Compose build arg 传入前端 Dockerfile。现在已完整接入，默认值明确为 60。
2. **自定义后端端口会切断 gateway。** 后端读取 `PORT`，但 gateway 与健康检查固定访问 3000。现在两处都使用同一个 `${PORT:-3000}`。
3. **CosyVoice 与主服务不在同一网络。** 覆盖文件把 `tutor-net` 改成 external，而主 Compose 使用项目名前缀网络，分步部署后 backend 可能无法解析 `cosyvoice`。现在主网络显式命名为 `tutor-net`，所有服务共用。
4. **gateway 与后端重复处理 CORS。** gateway 曾固定输出 `Access-Control-Allow-Credentials: true` 和通配来源，与后端白名单及浏览器规则冲突。现在 API CORS 和 OPTIONS 只由 Fastify 处理。
5. **部署证书读取路径错误。** 初始化工具把证书放在 `${AI_TUTOR_HOME}/data/certs`，上传逻辑却读取仓库 `data/certs`。现已统一读取前者，远端初始化也显式跳过无意义的 mkcert 安装流程。
6. **回滚可能删除大模型和缓存。** schema 变更后的回滚原先删除整个 data 目录，但备份主动排除了 Whisper/CosyVoice 模型。现在只恢复配置与数据库，保留模型及缓存目录；备份也跳过可再生成的大型缓存。
7. **SQLite 热复制可能不一致。** 原脚本在 backend 写入期间直接复制 DB/WAL/SHM。现在备份前短暂停止 backend，复制完成后立即恢复，后续耗时构建期间旧服务仍在线。
8. **旧数据库会跳过新迁移。** 无迁移元数据的旧库原先把所有当前及未来版本直接登记为已应用。现在历史基线固定为 1–2，版本 3 及后续迁移会真实执行，并有升级测试覆盖。
9. **非交互 setup 忽略显式环境变量。** `setup.sh --yes` 文档允许通过环境变量配置，但实现会忽略它们并生成 mock/browser 默认值。现在本地 setup 会读取显式环境变量；远程部署仍主动隔离本机 shell，避免覆盖生产密钥。
10. **配置校验过松。** 启用 ASR 时缺少密钥此前只是警告；占位 API key 也算有效。现在按 provider 阻止缺失/占位密钥，并校验端口、心跳、日志等级、角色 provider、FPS、DPR 与小米 TTS 模式。部署覆盖或沿用远端 `.env` 前均强制严格校验，`setup:set` 的拼写错误也会回滚。
11. **环境变量模板包含无效项。** `XIAOMI_TTS_VOICE_DESIGN` 以前会生成但后端不读取，现在已接入实际兜底音色；没有消费方的 `XIAOMI_TTS_ZH_VOICE_DESIGN` 已移除。
12. **容器停止时没有真正优雅关闭。** SIGTERM/SIGINT 处理器原先只打印“优雅关闭”后立即退出。现在会先停止 Fastify、关闭 SQLite，再退出；Compose 增加 init 进程和 15 秒停止宽限期。

## Node 服务保活边界

生产环境不需要在容器内再套 PM2。Node 是 backend 容器的主进程，`restart: unless-stopped` 负责在进程异常退出和 Docker daemon 随主机启动后重新拉起，健康检查负责暴露服务状态。

Docker restart policy 不会仅因为容器变为 `unhealthy` 就重启它。因此当前能自动恢复“进程退出”，不能自动恢复“进程仍在但事件循环或接口完全卡死”。个人项目现阶段保留这个边界，避免为 autoheal 挂载高权限 Docker socket；可通过外部监控告警后执行 `docker compose restart backend`。如果后续需要无人值守自愈，应由宿主机 systemd watchdog 或可信的运维平台根据 `/api/health` 重启服务。
