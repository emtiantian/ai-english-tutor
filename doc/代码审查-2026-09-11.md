## 一、优先修复的问题

### 1. P1：点击角色的请求丢失会话，回复无法进入当前聊天

- 位置：[remote-teacher.ts:25](/Users/haohe/Documents/code/codex/ai-english-tutor/apps/tutor-app/src/providers/remote-teacher.ts:25)、[TutorClient.ts:83](/Users/haohe/Documents/code/codex/ai-english-tutor/apps/tutor-app/src/client/TutorClient.ts:83)。
- `generateResponse()` 只发送 type/text/level，没有 sessionId/userId；TutorClient 不会自动补齐。后端于是生成新会话 ID，SSE 广播无法到达当前 connectionId；角色点击回调也没有把 HTTP 返回值写入 store。
- 结果：界面先显示用户消息和思考状态，实际请求脱离当前场景；还可能触发新会话未持久化时的消息写入失败。
- 建议：角色点击与文本、录音统一走一个提交入口，统一注入会话、用户、requestId 和错误收尾。移除这个只有外形统一、实际行为分叉的发送路径。
- 验收：进入场景后点击提示，回复继续当前场景且思考状态结束；失败时也能恢复输入。

### 2. P1：流式请求失败只记日志，前端可能一直“思考中”

- 位置：[chat.ts:99](/Users/haohe/Documents/code/codex/ai-english-tutor/apps/tutor-server/src/routes/chat.ts:99)、同文件 lesson.start 的异步 catch。
- HTTP 已返回 202，后续 LLM/解析/数据库错误只写日志，没有向 SSE 发送失败事件。前端虽然订阅 error，但收不到这个失败。
- 建议：所有请求必须有 success/error/cancelled 终态；返回带 requestId 的失败事件，前端清理流式消息、思考状态并提供重试。主动取消和服务故障分开处理。
- 验收：mock LLM 在若干 chunk 后抛错，UI 能结束等待并显示失败原因。

### 3. P1：打断只用本地代数，旧音频和新回复仍会串线

- 位置：[App.vue:265](/Users/haohe/Documents/code/codex/ai-english-tutor/apps/tutor-app/src/App.vue:265)、[useAudioPlayback.ts:98](/Users/haohe/Documents/code/codex/ai-english-tutor/apps/tutor-app/src/composables/useAudioPlayback.ts:98)、[response-orchestrator.ts:429](/Users/haohe/Documents/code/codex/ai-english-tutor/apps/tutor-server/src/ai/response/response-orchestrator.ts:429)。
- requestEpoch 只存在前端，SSE 数据没有对应 ID。新请求递增 epoch 后，旧请求迟到的 chunk/audio 也会通过过滤；teacher.response 本身没有过期过滤。TTS 管线没有接收 AbortSignal，LLM 已结束、TTS 仍运行时的打断不能阻止旧音频广播。
- `client.interrupt()` 没有等待且按 session 打断，网络乱序时也可能取消刚发出的新请求。
- 建议：请求、回复、音频统一携带 requestId；打断指定 requestId；服务端在 ASR/LLM/TTS 和持久化、广播前检查取消状态；前端按请求归属丢弃迟到数据。每个 session 明确串行或替换策略。
- 验收：A 的 TTS 延迟，打断后发送 B，再完成 A；A 不播放、不覆盖 B、不计入 B 的消息音频。

### 4. P1：词汇“已掌握”的自动达成路径断了

- 位置：[vocabulary.ts:110](/Users/haohe/Documents/code/codex/ai-english-tutor/apps/tutor-server/src/db/repositories/vocabulary.ts:110)、[vocab-tracker.ts:132](/Users/haohe/Documents/code/codex/ai-english-tutor/apps/tutor-server/src/ai/vocab-tracker.ts:132)。

- 建议：明确语境定义，在用户有效使用单词时记录去重语境，并在更新掌握状态前完成语境记录；或者先采用当前数据真正能支撑的掌握规则。

### 5. P1：没说某个复习词，被当成答错

- 位置：[vocab-tracker.ts:138](/Users/haohe/Documents/code/codex/ai-english-tutor/apps/tutor-server/src/ai/vocab-tracker.ts:138)。
- 每轮取到期复习词，用户文本中没有出现就调用 reviewWord(false)。自由对话未必给用户使用这些词的机会；连续三轮没提到，会被标记为 forgotten。

### 7. P1：在线同步漏掉新词，累计快照又虚增复习次数

## 三、值得做的实现优化

1. **优先收敛提交链路。** App、角色点击、录音共享一个 submitTurn；用请求状态（submitting/generating/synthesizing/playing/completed/failed/cancelled）派生 UI 状态，减少 isThinking/isPlaying/interrupted 等分散写入。
2. **学习数据分层。** 将“遇到”“使用”“考察正确”“掌握”拆开；先修正上述评分和词汇断点，再做长期画像，否则只是长期保存错误数据。
3. **减少数据库全量读取。** VocabTracker.processTurn 对每个 AI 单词都 getAllWords(userId).find；每轮一次查询建 Set，或使用按词查询/批量 upsert。会话恢复也全量读取历史、内存无限 push，而自由对话 prompt 只取最后 10 条；可保留数据库全量记录、内存只存近期窗口及独立统计。
4. **音频当前是“整段合成后分片发送”。** TtsOutput 等待完整 Buffer，再转 base64 并同步循环广播；不是能缩短首音延迟的流式 TTS。优先先按句合成播放，再按 Provider 能力接真正的增量音频；为 write(false) 增加背压处理，并让音频与 requestId/messageId 绑定。
5. **统一 API 运行时校验。** 多数路由只有 TypeScript 类型和零散 truthy 校验；例如 chat 的 text 为数字时，try 外的 text?.slice 就会失败。为 body/query/params 定义 schema，验证枚举、范围、长度，非法输入明确返回 400。流式 accepted 与完整响应也建议建判别联合类型。
6. **补跨模块测试，而非继续堆方法测试。** 优先覆盖点击角色保持会话、流式失败终态、打断后旧音频、在线/离线同步幂等、三语境掌握、未考察不扣分。当前 342 项测试全部通过，但这些业务不变量仍未被保障。

推荐顺序：请求身份与错误终态（1–3、10）→ 学习数据正确性（4–8）→ 恢复和配置（9、11、12）→ 删除无生产调用代码及性能优化。无认证已在旧 buglist 中明确作为个人用途的产品取舍，本次不将它重复列为紧急缺陷。
